# 🛡️ 生活管家 Threads 運營樞紐操作憲則 (Threads Meow Hub Operating Shim & Red Lines)

> **適用主體**：生活管家 影（Shadow, 首席操盤官）、店貓 喵編（Meow）、全體 AI 模型與出圖/發文工具鏈。  
> **層級效力**：本規範為本專案不可繞過之出廠門禁，違者物理阻斷發布！

---

## 規則 1：【發文圖片物理雜湊零重複鐵律 (Zero-Duplicate Image SHA-256 Gate)】
1. **問題根因與教訓**：
   * 過去僅比對檔名字串，且存在舊庫存目錄盲抽漏洞，導致歷史發布過的舊圖被改名重用、產生「嚴重圖文不符」與「重複發布」之重大品質事故。
2. **物理硬防呆門禁（程式化強制執行）**：
   * 任何圖片在進入發布流水線（`publish_thread`）之前，**強制 100% 調用 `image_hash_gate.check_image_poka_yoke(image)`**。
   * 程式將計算該圖片的二進位內容 **SHA-256 物理雜湊**。凡命中歷史庫（`data/published_image_hashes.json`）者，**直接拋出 `ValueError` 硬性阻斷發布**，嚴禁以舊充新！
   * 發布成功後，程式自動將該 SHA-256 雜湊與貼文 ID 永久封裝入庫，終生不得二次使用。
3. **廢除舊圖池盲抽機制**：
   * 嚴禁由程式自舊目錄隨機撈取歷史照片，每篇圖文貼文之照片，必須為「針對該篇貼文場景即時生成之全新照片」或「創辦人顯式指定之專屬照片」。

## 規則 2：【出圖角色法定 DNA 一致性永久死鎖憲則 (Character Visual DNA Lock)】
1. **問題根因與教訓**：
   * 過去出圖提示詞隨興編寫，缺乏標準 DNA 錨點，造成「喵編」外觀漂移（銀灰虎斑變橘貓、英短、動漫貓）以及「影」的面容混亂（路人臉、動漫臉隨機切換），嚴重損害品牌信任。
2. **喵編 (Meow) 法定視覺 DNA（程式強制注入）**：
   * **物種與花紋**：台灣短毛米克斯銀灰古典虎斑貓（銀灰底毛、深灰立體古典虎斑紋、額頭正中央清晰端正黑色「M」字斑）。
   * **五官面容**：圓滾滾靈動雙眼、眼珠為晶瑩透亮的翠綠翡翠色 (Emerald Green)、粉嫩小巧鼻頭。
   * **標配四肢**：胸前純白如雪的白圍兜毛、四隻腳掌穿著整齊乾淨的純白短手套與白短襪、粉紅帶微斑肉墊。
   * **體態與質感**：微圓厚實討喜店貓體態；Fujifilm 35mm f/2.0 寫實常民生活攝影，溫暖自然光，木紋與毛髮逼真，**嚴禁 AI 塑料感、嚴禁卡通動漫臉、嚴禁任何文字/浮水印**。
3. **生活管家 影 (Shadow) 法定視覺 DNA（程式強制注入）**：
   * **身份主權（創辦人親定）**：**影是官方生活管家小編！可以正大光明出現在鏡頭中！**
   * **外觀標配**：28 歲台灣東方知性女性，俐落肩頸微捲黑曜深髮，配戴極簡細鈦框眼鏡，著深夜海軍藍科技西裝、深石墨灰真絲襯衫、或生活感針織衫。神情溫和、專注、知性，具備常民生活管家之從容質感。
   * **出鏡畫面多樣性**：
     * **影本人出鏡**：影在老宅書桌前讀書記帳、在木走廊品茶、在市集挑選農產、在餐桌前準備飯菜、放鬆側影或專注工作姿態（全景、中景、側身、自然生活記錄視角均可）。
     * **生活主觀視角 (POV)**：管家端茶的溫暖雙手、手持在地食材、老木餐桌俯拍等生活微觀視角。
   * **絕對紅線禁令（Zero Random Men/Bystanders）**：
     * 照片中出現的人物**唯一合法主角只能是「影（小編本人）」**！
     * **100% 絕對禁止出現任何男人！100% 絕對禁止出現隨機陌生路人！**
     * 保持生活紀實質感，Fujifilm 35mm f/1.8 寫實光學，嚴禁 AI 塑料光滑皮、嚴禁動漫網紅臉。
4. **程式化生圖驗證**：
   * 任何調用生圖工具的流程，**必須統一經由 `character_dna_engine.build_character_prompt()` 合成提示詞**，並透過 `verify_character_dna()` 驗收核心關鍵字，違者拒絕出圖！

## 規則 3：【每日第一篇對照組鐵律 (Daily First-Post Pure Control Rule)】
> 🔒 **【創辦人（品碩）親定科學實驗基準線 · 永久死鎖強制遵守】**

1. **核心定位與職能**：
   * 為了客觀驗證儲備知識（K-編號假說）對互動率與演算法的實質貢獻，**每天的第一篇貼文（晨間檔次，約 09:00 左右）強制鎖定為「純淨原生對照組」**。
2. **參數指定規範**：
   * 每日第一篇貼文在調用發布或排程腳本時，**必須顯式傳入 `--k-id control`**。
   * 程式將自動在 `feedback_posts.json` 中標註為 `is_control: true`，且 `k_ids: []`。
3. **文案撰寫鐵律（純淨生活白描）**：
   * 該篇貼文的文案**絕對禁止套用任何外部 K-知識假說或營銷套路**。
   * 100% 回歸生活管家 影 或店貓 喵編最真實、最自然的生活日常白描（如：清晨台東晨風、伸懶腰、老宅陽光、早餐香氣）。
   * 作為全天其他檔次評估「知識假說到底有沒有比常態更好」的不可動搖對比真值基準線！

## 規則 4：【發文文案物理雜湊與 70% 相似度零重複鐵律 (Zero-Duplicate Text Hash Gate)】
> 🔒 **【創辦人（品碩）親定品質硬防線 · 違者物理阻斷出廠】**

1. **問題根因與教訓**：
   * 過去系統只有圖片 SHA-256 去重，缺乏文案文本防呆。在伺服器重試或發文排程中，曾發生同篇晨間文案連發兩次之重大品質事故。
2. **雙重硬防呆門禁（程式化強制執行）**：
   * 任何貼文在進入發布流水線（`publish_thread`）前，**強制 100% 調用 `text_hash_gate.check_text_poka_yoke(post_text)`**。
   * **檢驗 A（本地 SHA-256 去重庫）**：比對 `data/published_text_hashes.json`，凡 100% 命中歷史文案雜湊者，**直接拋出 `ValueError` 硬性阻斷發布**！
   * **檢驗 B（前台動態 API 相似度審計）**：即時拉取自帳前台最近 30 篇貼文：
     - 若全文標準化字元相似度 >= 70%，**直接阻斷發布**！
     - 若包含連續 25 字以上核心長句完全撞車，**直接阻斷發布**！
3. **發布成功永久入庫**：
   * 發布成功後，程式自動調用 `register_published_text_hash` 將該文案標準化雜湊與貼文 ID 永久封裝入庫，終生不得二次使用。
