## 🎯 一、 產品願景與商業定位

### 1.1 痛點解剖
* **官方政務 App 的沉重包袱**：「清運e點通」等官方系統層級過深，操作需要「選縣市 ➔ 選區域 ➔ 找路線 ➔ 縮放複雜地圖」，對於雙手拎著垃圾袋、趕著出門的家庭主婦、長輩或疲憊上班族極不友善。
* **常民核心需求**：民眾**不需要看懂整座城市的垃圾車跑去哪**，他只需要知道：
  1. **【最快】**：哪一班車最快到？我要幾分鐘內走過去？
  2. **【最近】**：離我家最近的點在哪裡？
  3. **【定點】**：今晚錯過了，台東市公所定點收運車在哪？

### 1.2 雙輪驅動定位
* **免費利民黑科技**：生活管家一鍵倒垃圾雷達（免下載 App、打開 LINE 1 秒即查）。
* **商業變現閉環**：追車好累、時間對不上時，下方自然浮現**「生活管家 999/1999 代倒包月」**。

## 🏗️ 二、 系統架構與資料流拓撲

1. **客戶端 (LINE LIFF / PWA)**：
   * 進入即自動要求 HTML5 Geolocation；若無授權，提供生活圈一鍵切換。
2. **後端計算引擎 (FastAPI / Serverless)**：
   * 雙軌機制：線上即時車機 API（主軌）＋ 台東市公所靜態表定站點資料庫（副軌兜底）。
   * 演算法：Haversine 空間直線距離與步行修正、ETA 時間過濾（當前時間 +3 ~ +25 分鐘）。
3. **決策卡片輸出**：
   * 🥇 **【火速攔截 (最快)】**
   * 🥈 **【從容慢走 (最近)】**
   * 🥉 **【錯過救急 (定點清運處)】**
   * 點擊任一卡片直接喚起 Google Maps 步行導航。

## 📋 三、 五階段衝刺排程 (Five-Phase Sprint Schedule)

* **Phase 1：資料逆向與資料集定錨 (Day 1 - 林納斯主導)**
  * 梳理台東市公所路線站點、經緯度、時刻表。
  * 嗅探中華電信「清運e點通」與環境部開放資料 API 端點與資料格式。
* **Phase 2：核心演算法與輕量 API 引擎 (Day 2 - 林納斯 ✕ 戴明)**
  * 實作最快/最近運算邏輯、台東在地【週三、週日】公所例行停收日防呆判斷、無車機降級機制。
* **Phase 3：Gentle UI 前端與 LINE LIFF 開發 (Day 3 - 尼奧主導)**
  * 打造極速手機端單頁應用（LINE LIFF），包含倒數呼吸燈卡片與一鍵導航。
  * 內嵌生活管家代倒垃圾 999/1999 溫暖導流入口。
* **Phase 4：現場實測與安燈驗收 (Day 4 - 戴明驗收)**
  * 台東市區 10 個核心點位實測與時間校準，出具綠燈驗收單。
* **Phase 5：LINE OA 上線與推廣發射 (Day 5 - 雪 ✕ 泰勒絲)**
