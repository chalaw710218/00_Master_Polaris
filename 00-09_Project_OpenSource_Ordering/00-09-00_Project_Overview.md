# 🚀 曉專案：開源點餐系統 (B2B 批發端佈局)

> **建立日期**：2026-09-28
> **更新日期**：2026-09-29
> **專案發起人**：董事長品碩 (CEO) / 曉企業
> **核心定位**：本專案為協助實體店家「合法避險」與「合法節稅」的線上點餐系統。我們從「B2C 外送平台」轉型為「B2B 系統租賃」，以「物流代送」避開高風險。

---

## 🎯 一、商業模式與定位 (Business Model)

1. **商業邏輯**：
   我們不向終端消費者「直接」收取平台費。我們是在提供一套「開源(Open Source)」建置的「單一店家」專屬線上點餐系統。
2. **獲利來源**：
   * **前端 (資訊端)**：向店家收取一次性的「系統建置費 / 租賃費」，以及後續的「月租費」。這筆費用可作為店家營運成本，有效合法節稅。
   * **後端 (物流端)**：消費者在店家專屬系統下單後，店家呼叫「外送車隊」進行配送。我們賺取 B2B 車隊媒合費。
3. **法律與風險隔離 (避險機制)**：
   在法律定義上，外送平台是「向消費者直接負責」的，我們則是「提供系統工具」與「代叫外送車隊」。這將能合法規避傳統外送平台的消保法爭議與勞資風險。

## 🚀 二、專案進度與技術路線 (Current Progress)

* **[✅] 階段一：底層基礎建設與 TastyIgniter 系統部署**
  * **成果**：成功於 GCP 免費層 (e2-micro) 部署 Ubuntu 22.04 + CloudPanel。
  * **成果**：完美克服 CloudPanel 雙層代理 (Nginx + Varnish) 導致的 HTTPS 混合內容與 CSRF 憑證失效問題。
  * **成果**：解決 PHP 8.4 版本不對稱與 MariaDB 鎖死問題，**成功部署 TastyIgniter v4 並登入超級管理員後台**。
  * **文件產出**：已產出《GCP_CloudPanel_TastyIgniter_V4_完整部署教學.md》。

* **[🔥 進行中] 階段二：實體店面硬體與物流整合 (硬體與車隊 API)**
  * **目標 1**：出單機串接 (Cloud Printers / ESC/POS)。消費者線上點餐後，實體店面廚房直接印出工單。
  * **目標 2**：外送機車車隊結合。訂單成立後，透過 API 自動呼叫外送車隊，進行即時配送與追蹤。

* **[⏳ 規劃中] 階段三：庫存管理、AI 預測與批發端自動化 (Supply Chain)**
  * **目標 1**：庫存管理與 AI 預測。從 TastyIgniter 每日銷售數據，預測明日需進貨的食材數量。
  * **目標 2**：批發端自動化叫貨。當系統預測庫存不足時，自動與「曉企業的批發端」結合，進行自動叫貨與物流配送，完成垂直整合。

* **[⏳ 規劃中] 階段四：定價策略與法務合約 (Pricing & Contracts)**
  * **目標**：決定「建置費」的買斷制/訂閱制價格，並草擬 B2B 租賃與物流代辦合約。

## 💼 三、曉企業的「一條龍」終極願景

1. **資訊流 (TastyIgniter 點餐系統)**：為店家建立獨立品牌線上通路，擺脫高抽成外送平台。
2. **物流 (車隊媒合與批發配送)**：消費者訂單由外送車隊配送；店家食材由批發物流配送。
3. **金流與商流 (垂直整合)**：從最源頭的「食材批發」👉「餐廳點餐 POS」👉「終端外送」，曉企業將掌握整條供應鏈的數據與金流，打造牢不可破的餐飲生態圈。
