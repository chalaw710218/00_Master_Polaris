### 衝突點一：GCP e2-micro 記憶體規格與 Free Tier 免費方案區域限制之邊界
- **現有事實庫（條目 5）**：
  - 核心事實／摘句：`e2-micro : 0.25 vCPU, 1 to 2 GB of memory`
  - 出處：https://cloud.google.com/compute/docs/general-purpose-machines
- **第 1 輪新學知識**：
  - 核心事實／摘句：GCP Free Tier 每月提供 1 個 non-preemptible e2-micro 執行體，且嚴格限制在美國三個區域（`Oregon: us-west1`、`Iowa: us-central1`、`South Carolina: us-east1`），並附帶 30 GB-months 標準磁碟與 1 GB 北美出站流量。
  - 出處：https://cloud.google.com/free/docs/free-cloud-features
- **衝突與差異說明**：
  - 現有條目 5 僅陳述機器硬體規格（1 to 2 GB 記憶體），易讓人誤以為任何區域建立 e2-micro 皆為免費。
  - 新學事實確認 Free Tier 免費配額嚴格綁定美區（us-west1, us-central1, us-east1），若在台灣（asia-east1）建立則無法享有免費額度。此處存在「硬體規格定義」與「免費計費資格」之邊界衝突。

### 衝突點二：TastyIgniter v4 依賴版本與極星既有輕量化環境之相容衝突
- **現有事實庫相關背景**：
  - 過去系統多以 PHP 8.1/8.2 與 MySQL 5.7 輕量環境進行配置以節省記憶體。
- **第 2 輪新學知識**：
  - 核心事實／摘句：TastyIgniter 最新標準需求為 `PHP 8.3+` 以及 `MySQL 8.0+ or MariaDB 10.6+`。
  - 出處：https://tastyigniter.com/docs/master/installation
- **衝突與差異說明**：
  - TastyIgniter v4 強制要求 MySQL 8.0+，但在 1GB 記憶體的 e2-micro 實體機上，MySQL 8.0 預設記憶體開銷顯著高於舊版，若未經深度調校將直接觸發 OOM Killer。新依賴標準與硬體邊界形成實務佈署衝突。

### 衝突點三：ESC/POS 網路列印出處權威度與協定定義之差異
- **現有事實庫（條目 4）**：
  - 核心事實／摘句：`TCP port on the printer (default port is 9100)`
  - 出處：https://en.wikipedia.org/wiki/AppSocket (維基百科第三方條目)
- **第 5 輪新學知識**：
  - 核心事實／摘句：`AppSocket printing normally happens over port 9100 and uses the socket backend.`
  - 出處：https://openprinting.github.io/cups/doc/network.html (CUPS 官方標準文件)
- **衝突與差異說明**：
  - 條目 4 依賴維基百科定義，而第 5 輪新學知識直接來自 CUPS 官方文件，定義其使用 `socket` 後端與裝置 URI 規範（`socket://ip-address`）。兩者 port 相同，但官方文件明定 backend 機制，存在出處層級與實作細節之差異。

### 衝突點四：Google Sheets API 單次呼叫限制 vs Batch 請求原子性計算衝突
- **現有事實庫（條目 1）**：
  - 核心事實／摘句：`read request limit of 300 per minute per project`
  - 出處：https://developers.google.com/sheets/api/limits
- **第 6 輪新學知識**：
  - 核心事實／摘句：`Each batch request , including any subrequest, is counted as one API request toward your usage limit. All Sheets requests are applied atomically. That is, if any request is not valid then the entire update is unsuccessful and none of the (potentially dependent) changes are applied.`
  - 出處：https://developers.google.com/sheets/api/limits
- **衝突與差異說明**：
  - 條目 1 僅指出每分鐘 300 次請求之硬配額。第 6 輪確認 batchUpdate 內的複數子請求合併計算為 1 個配額請求，但具備「全有或全無」之原子性（任一子請求錯誤則整批失效）。若業務邏輯依賴高頻分散請求將面臨配額瓶頸，依賴 batch 則面臨全部拒絕之容錯衝突。

### 衝突點五：SQLite 預設復原日誌模式 vs WAL 模式併發讀寫機制衝突
- **現有事實庫（條目 76）**：
  - 核心事實／摘句：`The default method by which SQLite implements atomic commit and rollback is a rollback journal`
  - 出處：https://www.sqlite.org/wal.html
- **第 10 輪新學知識**：
  - 核心事實／摘句：`WAL provides more concurrency as readers do not block writers and a writer does not block readers. Reading and writing can proceed concurrently.`
  - 出處：https://www.sqlite.org/wal.html
- **衝突與差異說明**：
  - 條目 76 記錄 SQLite 預設機制為 rollback journal（寫入時鎖定所有讀取）。第 10 輪確認 WAL 模式下讀寫互不阻塞可併發進行。兩者代表 SQLite 兩種互斥的持久化運作模式，若架構未顯式啟用 WAL，將無法享有併發讀寫特性。

### 衝突點六：Windows 平台預設字元編碼與 PEP 686 UTF-8 模式之環境衝突
- **現有事實庫背景**：
  - 本機作業系統為 Windows，預設控制台與檔案系統常受 ANSI/CP950 歷史編碼影響。
- **第 8 輪新學知識**：
  - 核心事實／摘句：`This PEP proposes enabling UTF-8 mode by default. With this change, Python consistently uses UTF-8 for default encoding of files, stdio, and pipes.` / `So this change mostly affects Windows users. When a Python program depends on the default encoding, this change may cause UnicodeError , mojibake, or even silent data corruption.`
  - 出處：https://peps.python.org/pep-0686/
- **衝突與差異說明**：
  - 在 Windows 上未顯式指定 `-X utf8` 或 `PYTHONUTF8=1` 時，舊代碼若仰賴系統預設 locale，切換至 UTF-8 mode 將可能引發 UnicodeError 或資料損毀。
