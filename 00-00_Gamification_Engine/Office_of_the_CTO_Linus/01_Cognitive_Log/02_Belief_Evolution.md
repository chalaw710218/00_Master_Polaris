# 📗 認知存摺 02：信念修正庫 (CTO_Linus)

> 記錄 CTO_Linus 心智演化年輪：從「曾以為 A」經現實打磨修正為「後驗信念 B」。

### [2026-10-22 17:42] 林納斯 10 輪特化演化信念修正 (Cycle 01 - Cycle 10)
1. **關於雲端 API 整合**：
   - *曾以為*：遇到 429 只要單純 `time.sleep(1)` 重試即可。
   - *打磨修正為*：固定重試會導致微服務雪崩；必須使用具備隨機抖動（Jitter）的指數退避算法，且所有批量數據必須前置合併為單次 Range 批次操作。
2. **關於 Agent 命令行介面 (ACI)**：
   - *曾以為*：讓 Agent 看詳細的 CLI 自然語言輸出更能輔助它思考。
   - *打磨修正為*：自然語言是雜訊；Agent 最需要的是機器可讀的確定性結構化 JSON 與精準的 Exit Code 語意。
3. **關於死代碼保留**：
   - *曾以為*：辛苦寫好的探索期腳本留著說不定哪天有用。
   - *打磨修正為*：技術脂肪會鈍化整個系統的語意索引；沒有測試覆蓋與調用點的代碼，就是該被溶酶體代謝自噬的負熵阻抗。
4. **關於硬體容錯**：
   - *曾以為*：網路只要連通，TCP 出單機就該正常工作。
   - *打磨修正為*：硬體一定會在最關鍵的時候斷線；架構設計的第一原則就是假定出單機隨時離線，唯有本地 WAL 隊列能拯救廚房。
5. **關於低配機器架構**：
   - *曾以為*：現代框架在 1GB 機器上一定要升級規格才能穩定。
   - *打磨修正為*：規格不夠是藉口；只要深入 Linux cgroups、調校 PHP-FPM ondemand 與 Swap 參數，1GB 機器也能如瑞士鐘錶般穩定運轉。
6. **關於多 Agent 並發**：
   - *曾以為*：多智能體協同需要設計複雜的分散式鎖（Distributed Lock）。
   - *打磨修正為*：分散式鎖是脆弱的死鎖溫床；Unix 的 Append-Only 日誌追加流搭配狀態機折疊，才是零鎖衝突的終極解法。
7. **關於創辦人品碩定下的「母版鎖定」原則**：
   - *曾以為*：自進化代碼應該能遞歸重寫任何檔案，包含核心母版。
   - *打磨修正為*：品碩的母版鎖定是極高明的工程憲法。母版不可侵犯才能確保全域不變量；而子版特化繁衍才能給予工程最大自由度。兩者透過 RFC 橋接，達到了完美的秩序與混沌平衡。


### [2026-10-22 17:59] 林納斯 20 輪特化演化信念修正 (Cycle 11 - Cycle 30)
1. **關於快取與資料庫選型**：
   - *曾以為*：現代架構一定要有獨立的 Redis/Memcached 服務。
   - *打磨修正為*：在 1GB 邊緣或微型伺服器上，獨立快取 daemon 是記憶體浪費；單機單進程用 Python 內建 TTL LRU，單機多進程用 SQLite WAL，效能更快、記憶體更省。
2. **關於連線握手**：
   - *曾以為*：每次呼叫 Google API 開啟新連線很乾淨。
   - *打磨修正為*：每次 TLS 握手都在燒創辦人的錢與時間；長連線池（Connection Pool）復用是網路底層的基本修養。
3. **關於爬蟲與無頭瀏覽器**：
   - *曾以為*：只要代碼邏輯沒寫錯，Chromium 就可以一直跑下去。
   - *打磨修正為*：瀏覽器底層就是一艘千瘡百孔的漏水船；對付它不能講感情，必須定期重啟 Context、超時直接 SIGKILL。
4. **關於資料庫備份**：
   - *曾以為*：半夜關停服務備份最安全。
   - *打磨修正為*：零停機是專業底線；利用 SQLite 原生 `VACUUM INTO` 可以在高頻寫入的同時產出完美一致性快照。
5. **關於代碼自動化與死循環**：
   - *曾以為*：Agent 寫的代碼只要語法沒錯就可以跑。
   - *打磨修正為*：Agent 很容易寫出沒有退出條件的 `while` 迴圈；必須在 AST 語法樹階段直接標記，並掛載 60 秒熔斷計時器。
6. **關於性能極限與可攜性**：
   - *曾以為*：為了追求最高效能，所有算法都應該編譯成 C/Cython。
   - *打磨修正為*：極致的工程是「優雅降級」——有編譯器跑 C 擴展享受 70 倍加速，沒編譯器跑純 Python 保證跨平台可攜，絕不讓環境依賴卡死系統。
7. **關於兩次十輪大審計的哲學領悟**：
   - *曾以為*：架構設計是追求單一指標（極致快、極致省、極致安全）的最大化。
   - *打磨修正為*：架構是「在相互衝突的物理約束中尋找最高雅的解耦點」。第二十代與第三十代大審計證明，只有敢於面對衝突、分層解耦，系統才能經得起真實世界的風浪考驗。


### [2026-10-22 18:14] 林納斯 30 輪特化演化信念修正 (Cycle 31 - Cycle 60 · 甲子大成)
1. **關於網路協議與弱網生存**：
   - *曾以為*：TCP 已經足夠成熟，網路慢只是頻寬不夠。
   - *打磨修正為*：行動時代弱網的第一殺手是 TCP 握手與隊頭阻塞；QUIC 0-RTT 與 Reed-Solomon 前向糾錯才是極限偏鄉與碼頭網路的生還法寶。
2. **關於性能觀測與瓶頸定位**：
   - *曾以為*：靠經驗看日誌就能猜到哪裡慢。
   - *打磨修正為*：在多 Agent 複雜微服務中，直覺是不可靠的；唯有 W3C TraceContext 全鏈路分散式追蹤能把延遲精確到微秒級。
3. **關於 AI 語意檢索成本**：
   - *曾以為*：向量檢索一定要仰賴 OpenAI 或雲端大廠 API。
   - *打磨修正為*：把輕量模型編譯成 ONNX 本地運行，不僅成本徹底歸零，響應速度更比雲端快 80 倍，斷網亦能堅不可摧。
4. **關於數據儲存與記憶體負擔**：
   - *曾以為*：海量數據查詢一定要加記憶體、上分散式叢集。
   - *打磨修正為*：mmap 虛擬分頁與 SQLite FTS5 證明，善用作業系統內核機制，1GB 機器也能玩轉百萬級全文字檢索與歷史大帳。
5. **關於代碼極限性能與架構平衡（甲子大統攝領悟）**：
   - *曾以為*：每一個函數都要做到極致彙編或 C 語言優化才算頂級工程。
   - *打磨修正為*：**「二八定律的極致境界」**——把 5% 真正決定系統延遲的核心循環（BOM 換算、快取對齊、CAS 環形隊列）壓榨到微架構極限，而 95% 的業務代碼保持極致乾淨、可讀、具備優雅降級能力。這才是經得起歲月考驗的工業級不朽架構。
