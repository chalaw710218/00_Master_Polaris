### 一、 QA 過程審查清單 (Pre-flight Checklist · 上線前必備)

在任何代碼合併到主分支，或執行每日收工關機程序前，系統必須依序檢核以下 6 項指標：

- [ ] **QA-01 (Windows 終端編碼防呆)**：Python 腳本是否在檔頭配置 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，防範 CP950 崩潰？
- [ ] **QA-02 (網路請求逾時與例外保護)**：所有對外 HTTP/GAS/API 呼叫是否包覆 `try...except` 並設定 Timeout 與重試上限？
- [ ] **QA-03 (本機離線執行驗證)**：修改之腳本是否已於本機實際執行測試，且返回碼為 Exit Code 0？
- [ ] **QA-04 (資安與敏感金鑰解耦)**：代碼與設定檔中是否 100% 杜絕寫死 API Key / Token（必須統一透過 `.secrets.env` 載入）？
- [ ] **QA-05 (日結金流零差錯對帳)**：每日 01:00 日結時，當日外送現金、線上收款、代墊支出與公積金帳本是否 100% 勾稽平衡，無任何未明差額？
- [ ] **QA-06 (Git 乾淨提交與備份推送)**：當日戰果與設定檔是否已全數 Commit 並 Push 至遠端 GitHub 雲端倉庫？

### 二、 QC 產物驗收評分標準 (Acceptance Criteria · 總分 100 分)

| 評分維度 | 權重 | 檢驗標準細節 | 扣分條件 |
| :--- | :--- | :--- | :--- |
| **系統魯棒性與防呆** | 30% | 邊界條件保護、例外捕捉、編碼安全 | 缺少編碼防呆或例外保護扣 15 分 |
| **代碼簡潔與無冗餘** | 25% | 直擊資料結構、無多餘依賴、無過度封裝 | 冗餘代碼或死循環風險扣 10 分 |
| **日結帳目 100% 平衡** | 25% | 財務金流零差額，帳物相符 | 出現未解釋差額扣 25 分（直接不及格） |
| **版本控管與資安** | 20% | Commit Message 語義化，無金鑰外洩 | 洩漏敏感資訊扣 20 分（直接 Andon 阻斷） |

### 🚨 三、 安燈繩 (Andon Cord) 物理阻斷紅線

**只要出現下列任一情況，綜合評分直接歸零，系統物理攔截，嚴禁合併或關機：**
1. ❌ **代碼中出現明文 API Key 或 Token。**
2. ❌ **執行時拋出未捕獲之致命崩潰（Exception / Crash）。**
3. ❌ **收工帳目存在哪怕 NT$ 1 元之未平帳差額。**
4. ❌ **綜合品質評分低於 90 分者。**
